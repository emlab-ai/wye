# New type instances and comments go to a home document

## Request

> need to chnage now we create new instances of a type, i.e. i created type cities, then i from somewhere add new instance London of type city, city:London, if i do it from just selected text it is not clear, on where to store, so the idea in this case to create new document Cities, which will have collection of cities by default. the same i.e. with comments, if i click to any node and add comment - it must store it in the Comments document, but add link to node I clicked

*refs: *type:city

## Context

**What you want** — When a person creates a new instance of a type (like city:London) or adds a comment on a node, the system should know where to store it instead of leaving that ambiguous. Each type should have a default home document (e.g. a Cities document collecting all city instances), and comments should similarly land in a dedicated Comments document, each new block linked back to the node it was created from or attached to.

**Touches** — requirements-documents: req:wf2.page.create-typed, req:wf2.editor.entity-from-text, question:wf2.page-instance-add · requirements-ontology: req:ontology.type-page, question:ontology.child-nodes, req:ontology.add-type · plan: task:ontology.add-type · : type:city · pr-27: task:pr-27 · pr-26: task:pr-26

**Already there / in the way** — question:ontology.child-nodes already asks exactly how a comment-as-child-node should be written in markdown — this request answers it with 'a Comments document, linked to the node' question:wf2.page-instance-add asks almost this same question for type instances — whether '+ add' should create a page/document instead of a card; this request proposes a default per-type collection document as the answer req:wf2.editor.entity-from-text is the 'select text → make node' gesture this request says is unclear about storage location
